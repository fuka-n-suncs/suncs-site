# コンテンツの置き方

記事・お知らせ・事例はすべてここに Markdown で置く。ファイルを追加すればページが増える。

## フォルダ構成

```
src/content/
├── news/          お知らせ（プレスリリース・登壇・メディア掲載）
├── media/         メディア（記事・お役立ち資料）
└── cases/         導入事例
```

## 2つの書き方

### 画像がない記事 → 1ファイル

```
news/spring-release.md      →  /news/spring-release
```

### 画像がある記事 → 1フォルダ

```
media/cs-onboarding/
├── index.md                →  /media/cs-onboarding
├── eyecatch.jpg
├── figure-1.png
└── figure-2.png
```

**ファイル名（フォルダ名）がそのままURLになる。**
英小文字とハイフンで付ける（例: `cs-onboarding`）。日本語は避ける。

`_` で始まるファイル・フォルダは読み込まれない。`_template/` をコピーして使う。

## アイキャッチ画像

記事フォルダに画像を置き、frontmatter に相対パスで指定する。

```yaml
eyecatch: ./eyecatch.jpg
eyecatchAlt: 画像の内容を説明するテキスト
```

- 推奨サイズ: **1200×630px 以上**（OGPと同じ比率）
- 形式: JPG または PNG。圧縮せず元データのままでよい
- ビルド時に WebP へ変換され、表示サイズに応じた複数解像度が自動生成される

## 本文中の画像

同じフォルダに置いて、Markdown から相対パスで参照する。

```markdown
![画像の説明](./figure-1.jpg)
```

これだけで最適化の対象になる。`[]` の中の説明文は読み上げと検索に使われるので、
装飾目的でない画像には必ず書く。

### やってはいけない参照

| 書き方 | 何が起きるか |
|---|---|
| `![](https://旧サイト/img.jpg)` | 旧サイトが閉じると画像が消える。最適化もされない |
| `![](/images/img.jpg)`（public/ 配下） | 表示はされるが最適化されず、キャッシュも効きにくい |

**旧サイトから記事を移行するときは、画像もダウンロードして記事フォルダに入れる。**

## 公開するには

frontmatter の `draft` を `false` にする。`true` の間はページ自体が作られない。

## 旧サイトからの移行

移行した記事には元のURLを記録しておく。

```yaml
originalUrl: https://sun-cs.co.jp/news/xxxx
```

公開後、旧URLから新URLへの301リダイレクト設定が必要かどうかの判断に使う。
